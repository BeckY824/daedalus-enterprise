口径来源：方案稿 E-277（客户回「按默认执行」）+ 我方回复 E-280（客户回「按草稿」，E-288）。两者有出入的以 E-280 为准。
机制总表相关行：X-166、P-删-01 / 03 / 05 / 10、P-看-10、P-沟通-03。代码基线 16e3ca6e。

本文分七节：一、口径摘要（这一单照什么做）；二、逐表挪 / 不挪；三、撤回怎么做；四、入口清单；五、分阶段计划；六、要定的点（总控已定）；七、第二阶段补的：合成联系人、项目换客户、服务端动作。

## 二、逐表挪 / 不挪

记号：**挪** = 改成留下那家（下称 A），被并那家下称 B；**去重** = 改指以后和 A 已有的撞上，删掉 B 那一行（行内容整行记进合并单，撤回时建回）；**不挪** = 留在 B 身上。
「含回收站里的」= 早些时候单独删掉、还在回收站的那几条也一起挪（否则它们挂在一位已并入的客户下，以后恢复不了）。

### 2.1 客户本身

| 表 / 格 | 结论 | 理由 |
| --- | --- | --- |
| Customer（B 这一行） | 软删：只写 B 的 `deletedAt`，**不连带**（连带的子行都已挪走）；合并单记「已并入 → A」 | 回收站 30 天清掉，和撤回期限一致 |
| A 的资料格 | **只补空**：A 空着、B 有值的格用 B 补；两家不同的格在预览里并排列出 | E-277「以留下那家为准，空格用被并那家补」 |
| 补空的格（Customer） | `shortName`、`customerType`、`customerAttr`、`bizLine`、地址五格（**整组**：A 五格全空才整组拿 B 的，免得拼出半个地址） | 同上 |
| 补空的格（CustomerExtra） | `country`、`website`、`level` | 同上 |
| 不补的格 | 来源：`channelId`、`touchpoint`、`channelOwnerId`、`attributionChannelId` 照 A；`remark`、`custStatus`（重算）、`assignWay`、`archiveTier`、`flowLine`、`expectedSign*`、`poolInvalidAt`；CustomerExtra 里的 `whatsapp / wechat / email / alibabaId / source` | 来源按勾选口径「按留下那家」；号码类格是查重键，抄过来会和回收站里的 B 撞号（P-全局-09） |
| `referrerCustomerId`、`attributionCustomerId`（别的客户指着 B） | **挪**：改指 A；A 自己指着 B 的改成空 | 不改就指着回收站里的空壳 |
| `poolReturns` | **挪**：A 加上 B 的次数（合并单记差值） | E-277「退回次数也挪到留下那家，公海回避照认」 |
| CustomerCreator（B 的创建人） | **不挪**，记进合并单 `fromCreatorId` | E-280 三.3「创建人记在合并单里可查」 |
| CustomerClaim（B 的领取记录） | **不挪** | 只管 B 自己掉不掉公海；A 有自己的 |
| CustomerPool（B 在公海） | 只有「两家都在公海、系统管理员并」时才有：**删掉 B 那一行**（整行记进合并单） | 一家在公海一家不在的先领，进不到这一步 |
| EntCustomerClock（B 的三态钟） | **不挪**；A 合并后按合起来的沟通和项目重算一次（`存沟通后重算三态`），合并本身不算动静 | E-277「合并本身不拨钟」 |
| EntCustomerStateLog | **不挪** | B 自己的经历 |
| CustomerOwnerLog | **挪** | E-277「历史负责人挪到留下那家，公海回避照认」 |
| CustomerNoSeq / `customerNo` | 不动：B 的编号不改不复用 | E-277 |
| AuditLog | **不挪**；A、B 各写一条 `merge`（撤回各写一条 `merge-undo`）。AuditLog 不建外键，B 清掉以后按 `entityId` 照样查得到 B 的历史变更，所以不用另抄 | — |

### 2.2 客户级挂件

| 表 | 结论 | 理由 |
| --- | --- | --- |
| Contact（主客户是 B 的） | **挪**，含回收站里的；B 的关键联系人在 A 已有关键联系人时去掉关键标（记原值） | 一位客户一个关键联系人 |

### 2.4 合并之后重算

同一个事务里：A 的客户状态（`重算客户状态`）、最近跟进（按没删的沟通取最晚，同号留痕不算）。
事务提交后：A 的三态（`存沟通后重算三态`）；发通知；清可见范围缓存。

### 2.5 新表 EntCustomerMerge（合并单，迁移 171）

一单一行；挪动明细存 JSON（`detail`），够原样撤回。给第二批留的口子：

- `kind`：`客户`（这一单）/ `项目`（第二批「并进另一个项目」，`fromId / intoId` 存项目 id）
- `parentId`：第二批项目合并挂在哪张客户合并单下，整单撤回时一起撤；单撤一个项目的合并 = 撤这一行
- `status`：`已合并` / `已撤回`；第二批加 `待同意` / `已拒绝` / `已作废`（合并申请）
- `approvals`：第二批合并申请要同意的人和各自结论（JSON），这一单不写
- `fromName / fromNo / fromOwnerId / fromCreatorId / fromChannelId / fromTouchpoint`：B 当时的样子，B 清掉以后照样看得到
- `counts`：各类挪了几条（预览、日志、界面用）
- `undoneAt / undoneById / undoLeft`：撤回时间、谁撤的、没还原的那几条和原因

## 三、撤回

**谁能撤**：合并的人本人，或系统管理员。**期限**：合并后 30 天内，且 B 还没被清掉；A 在回收站里先恢复 A 再撤。

**怎么撤**：一个事务，照合并单倒着做：

1. 挪过的每一行，**只比合并写过的那几格**（导入撤回的做法，`revert.ts` 的 一致()）：现在还是合并写下的值 → 改回原值；已经不是了（之后被人或别的功能改指到别处）→ 不动，记进 `undoLeft`，撤回结果里写「留下 N 条，原因…」。
   - 合并没写过的格不比：项目之后换了负责人、结束了、进了回收站，照样回 B，负责人、结局不动（E-277「挪过来的项目后来被转走或结束的，照样回原客户」）。
   - 之后被彻底删除的，跳过、记一句。
2. 去重时删掉的行（ContactCustomer、ProjectCustomer、EntCustomerLink、CustomerPool）照整行建回；建回时已有同样的一行（之后又有人加上）就跳过。
3. 补空的格：A 这一格还是补进去的那个值 → 清回空；被人改过 → 留着，记进 `undoLeft`。
4. 关键联系人标、项目来源补的、重复咨询原始客户和序号、待处理挂靠申请的审批人：同第 1 条，还是合并写下的才改回。
5. `poolReturns`：A 减回差值（不减到负数）。
6. B 的 `deletedAt` 清空、从回收站回来；A、B 各写一条 `merge-undo` 日志；合并单记 `已撤回`。
7. 合并之后在 A 上新记的沟通、新建的项目、新加的联系人不跟着回去（合并单里没有它们）。
8. 提交后 A、B 都重算客户状态、最近跟进、三态。

**不半撤**：同一个联系人的主客户、挂靠行、关键标是一组；同一个项目的客户、来源、重复咨询是一组：组里合并写过的格有一格对不上，整组留下不撤（同 `revert.ts`「带走对不上话」）。

超过 30 天：不能整单撤回（第二阶段起用「项目换客户」一个个挪；项目换客户本身不在这一单，见第六节）。

## 七、第二阶段补的（11-25）

### 7.1 合成联系人（`src/lib/enterprise/contact-merge.ts`）

- **两个入口**：合并预览里勾「是同一个人」（留 = A 的联系人，并 = B 的联系人，`执行合并` 的 `同一个人`）；客户详情里单独合成（同一位客户名下两位，`合成联系人`）。
- **谁能合成**：单独合成 = 客户负责人本人（能删客户的角色）或系统管理员，公海里的先领；合并时勾的随合并的权限。
- **收到留下那位**：号码（ContactMethod，`kind + numberKey` 相同的删「并」那行、整行记下）、沟通、附件 / 名片、项目主联系人、项目联系人（同一项目两位都在的去重）、挂靠（同一客户两位都挂的去重）、卡点、同步对照。资料格只补空（职位、性别、生日、爱好、地址、备注、老号码三列）；「并」身上的老号码三列清空（免得回收站查号撞上、查重捞回把他捞回来）。「并」是关键联系人、「留」不是的，「留」接过关键标。
- **「并」那位**：软删进回收站，标「已合成 → 留」，不能单独恢复、彻底删除。
- **合成单**：EntCustomerMerge，`kind = 联系人`，`fromId = 并`、`intoId = 留`；合并时勾的 `parentId = 客户合并单`。
- **撤回**：单独合成的 30 天内合成的人或系统管理员撤（`撤回合并单` 同一个入口）；合并时勾的只能随整单撤回（先拆开、再随联系人挪回 B）。只比合成写过的格，对不上的记进没还原；删掉的号这会儿已挂到别处的不建回。

### 7.2 项目换客户（`src/lib/enterprise/project-move-customer.ts`）

- **挪什么**：Project.customerId；挂在这个项目上的沟通（含回收站里的）；卡点冗余的 customerId；项目关联客户里本来就有目标客户的那行删掉；重复咨询原始客户是原客户的改指目标、序号接在后面。附件挂项目 / 沟通，不用动。
- **不挪**：负责人、组员、节点、阶段、结局、项目来源、回款、提成；必填拦截记录照旧记当时的。
- **项目联系人**：还是原客户的人，挂靠到目标客户（ContactCustomer，说明「随项目换客户挂过来」），在目标客户页看得到；已挂着的、主客户就是目标客户的跳过。这样原客户名下别的项目还能用同一位联系人。
- **拦法同合并**：两位客户都是自己负责（能删客户的角色），这个项目没结束的话负责人也要是自己；交接中、标了无效、业务线不同、一家在公海一家不在都拦；两家都在公海只有系统管理员能换。订单阶段、有回款的也能换，预览列明。系统管理员可代换，代换时项目负责人、两位客户负责人（不是操作人本人的）各收一条通知（同第六节第 3 条，我方加的）。
- **不单独撤回**：换错了再换回去；日志项目、两位客户各一条 `project-move-customer`。

### 7.3 服务端动作（`src/app/(app)/customers/merge-actions.ts`）

`搜合并候选`、`预览合并`、`合并客户`、`撤回合并单`、`合成两位联系人`、`预览项目换客户`、`给项目换客户`、`并进来的合并单`。都先 `requireUser`（未登录 401，权限表已录），参数只认 id 和 `已核对 === true`、`同一个人` 的 `{留, 并}`；预览前查两家都看得到（走带限定的 prisma），看不到不给，免得拿 id 探别人的客户资料。
